# Что такое блокчейн?

**Блокчейн** — это три идеи, стоящие одна на другой:

1. **Журнал только для записи (append-only ledger)** — список транзакций, в который можно только добавлять данные, но нельзя редактировать или удалять.
2. **Цепочка хешей (hash chain)** — каждый блок содержит хеш предыдущего блока, поэтому изменение любой старой записи нарушает целостность всех последующих блоков.
3. **Протокол консенсуса (consensus protocol)** — способ, позволяющий множеству независимых компьютеров договориться о том, какой список транзакций является «настоящим», не доверяя друг другу.

Каждая из этих идей сама по себе старше блокчейна. Логи «только для записи» лежат в основе любой современной базы данных. Цепочки хешей были изобретены для цифровых меток времени в 1991 году. Консенсус — это работа в области распределенных систем, которой уже несколько десятилетий. Суть блокчейна в том, чтобы склеить все три идеи вместе так, чтобы *ни одна сторона не владела журналом единолично*.

## Почему «блоки»?

Транзакции объединяются в **блоки** для эффективности: согласование каждой транзакции по отдельности было бы слишком медленным. Блок — это просто пачка транзакций. Обычно в Bitcoin это транзакции за 10 минут, а в Ethereum — за 12 секунд.

Каждый блок содержит:

- Ссылку на предыдущий блок (`parent_hash`).
- Список транзакций.
- Метаданные (метка времени, майнер / валидатор, сложность / общая ставка и т.д.).
- Хеш самого себя, который используется следующим блоком для формирования цепочки.

Если вы измените одну транзакцию внутри блока N, его хеш изменится. Это означает, что `parent_hash` блока N+1 больше не совпадает, и цепочка «рвется», начиная с блока N. Чтобы подделка прошла успешно, вам придется переделать каждый блок от N до текущего конца цепочки — именно это протокол консенсуса делает непомерно дорогим.

## Взгляд со стороны платформы

В этой лабораторной работе вы будете работать с четырьмя реальными сетями: **Bitcoin** (модель UTXO), **Ethereum** (аккаунтная модель с газом), **Tron** и **Polygon** (L2 для Ethereum). Каждая сеть скрыта за единым интерфейсом `ChainAdapter`, поэтому остальная часть платформы может работать с ними одинаково:

```php
interface ChainAdapter
{
    public function currentHead(): BlockHeight;
    public function fetchBlock(BlockHeight $h): RawBlock;
    public function broadcast(SignedRawTx $tx): TxHash;
    // ...
}
```

Это единообразие позволяет нам написать один модуль сканера, который следит за всеми четырьмя сетями, один воркер вывода средств, который отправляет транзакции во все четыре сети, и так далее. Конкретные различия (UTXO против аккаунтов, газ против пропускной способности) находятся внутри каждого адаптера.

## Где это находится в коде

- `app/Modules/Network` — реестр сетей + контракт `ChainAdapter`.
- `app/Modules/BlockIngestion` — сканер, который превращает блоки из сети в строки в нашей базе данных.
- `app/Modules/Confirmation` — счетчик, который сообщает нам, когда транзакция зашла «достаточно глубоко», чтобы считаться окончательной.

Следующий урок посвящен криптографическим примитивам, которые делают все это возможным: **криптографии с открытым ключом и цифровым подписям**.
